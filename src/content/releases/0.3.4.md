# Prelimina 0.3.4

Stable setup and result formats, unified monitors and outputs, and steadier multiphase FLIP

## Changes

### Updating projects

- Setups now use the stable format version 1.0.0. Files from 0.3.2 and earlier (1.0.0-beta.11) are no longer opened. Convert them once with the offline converter `scripts/migrate_setup_beta11.py` from the source repository, or edit them by hand. The bundled examples are already converted.
- FLIP variants are named `single_phase`, `passive_gas` and `multiphase`. FVM and FIRM use `single_phase` and `multiphase`.
- The MultiFLIP and Wavelet Fluids methods have been removed from FLIP.
- Optional features such as thermal, waves, coupling, the sealed ullage and compressible gas are switched on by including their block. Their `enabled` flags are gone.
- All inflow is declared in a single `scene.inlets` list, and outlets accept fewer alternative spellings.
- FLIP and FIRM take viscosity and rheology from the phase definitions. Settings the selected solver would ignore are now reported as errors instead of being silently dropped.
- The `observables` block is now `monitors`. Probes, tracers, run-up, interface moments and body loads all go to the measurements file and the live graphs. Bodies are referenced by name everywhere.
- Output settings no longer assume VTK: `output.directory`, `output.every`, `output.every_s` and `output.metrics`, plus a new `output.format` that selects XML or legacy VTK. The matching command-line flags are `--output-dir`, `--output-every`, `--output-every-s`, `--output-format` and `--metrics`. The command line now uses the setup's output block as its defaults.
- Simulation results use the stable result format 1.0.0 and report the setup version they were loaded with.
- FLIP checkpoints written by earlier versions may not resume; restart those runs.
- `--validate` now succeeds when a setup has only warnings. Add `--strict` to treat warnings as failures.

### FLIP

- Two PBD iterations now run with the density projection by default. This keeps particles evenly spaced and roughly halves the volume error in sloshing and dam-break cases. An authored iteration count, including 0, is kept.
- Passive-gas simulations can use the density projection and no longer limit the time step by gravity.
- Multiphase pressure solves apply one consistent operator to every row, including outlets, isolated regions and compressible gas.
- Phase-field FLIP contact lines support dynamic contact angles, advancing and receding angle hysteresis, and the wall-distance contact fit. With a physical slip length, the angle is now imposed at grid scale (Cox model).
- Phase-field FLIP keeps the two phases apart near the interface and applies viscosity on cut-cell walls.
- Viscous mesh inlets support velocity profiles, yield-stress rheologies, temperature-dependent viscosity, and several constant-pressure or hydrostatic outlets.
- Moving and curved mesh inlets can use a staircase pressure boundary, with implicit viscosity and density projection. Existing particles no longer cross moving inlet caps.
- Density projection can be enabled on prescribed morphing walls.
- The particle phase tag of phase-field FLIP is available in exported results.
- A sealed ullage with a moving or deforming body is now rejected instead of running incorrectly.
- A case directory that has been moved can still resume its checkpoint.
- Linear viscosity solves need fewer GPU round trips, and phase-field contact reinitialization no longer waits on the host.

### FVM and FIRM

- FVM takes the hydrostatic reference from the outlets when it is not authored, and flooded single-phase starts no longer need a passive void.
- FIRM supports the shared dynamic contact angle and hysteresis, starts level still water with the correct free surface, and checks thermal convergence on the GPU.

### Viewer

- The settings tour points to its button, and weightless scenes orient their floor from the fill's waterplanes.

Breaking changes: existing projects or workflows may need changes before use.

## Requirements and limitations

These binaries are unsigned. A Vulkan-capable GPU and vendor driver are required. CUDA and macOS packages are not included. Back up projects and keep them outside the installation directory.
